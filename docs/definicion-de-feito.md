# Definición de feito

Contrato de verificación: unha tarefa está **feita** cando pasan todas as comprobacións que lle tocan; a base técnica, cando pasan **todas**. Cada unha ten comando exacto, resultado esperado e dono. Ninguén marca «feito» sen executar o comando. Os comandos comparan valores (`test …`), non dependen do código de saída de `grep -c`.

**DoD conxelada (ARQ3-3, 2026-10-23):** non entra ningunha fila nova salvo para cubrir a regresión dun fallo real; un caso novo dunha garda vai dentro da súa fila. **Dous carrís:** en cada cambio, `scripts/rapido.sh` (sen Docker, < 3 min: formato, D12 con autoprobas, unitarios da API, lint, i18n, formato, unitarios e tipos da web); o contrato enteiro, con `scripts/verificar.sh`, na CI e antes de cada etiqueta ([ADR-0016](adr/0016-ci-e-verificacion.md)).

**Como executar:** desde a raíz do repo, despois de `source scripts/entorno.sh`, que:
- antepón Node 24 ao `PATH` e exporta `DOCKER_HOST=unix://$HOME/.colima/default/docker.sock`, `TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE=/var/run/docker.sock`, `TESTCONTAINERS_RYUK_DISABLED=true`, `MAVEN_OPTS=-Xmx1g`;
- define `api_ut 'Clases'` = `(cd api && ./mvnw -B test -Dtest='Clases' -Dsurefire.failIfNoSpecifiedTests=true)`;
- define `api_it 'Clases'` = `(cd api && ./mvnw -B verify -Dtest=none -Dsurefire.failIfNoSpecifiedTests=false -Dit.test='Clases' -Dfailsafe.failIfNoSpecifiedTests=true)`.

Nas táboas, `\|` lese `|` (escape de Markdown). `jacoco:check` só se activa co perfil `-Pcoverage` (D11); os comandos parciais non fallan por cobertura. `scripts/verificar.sh` executa todo en orde (D42). Por defecto D12–D20 e D50 lense dos informes de D11 (cada clase nomeada correu, tests > 0, 0 fallos, erros e omitidos), porque xa corren alí e repetilos dobraría o tempo; así o fai a CI. Son a mesma proba (mesmas clases, mesmo build), non unha lectura de segunda man: un informe que falta, con 0 tests ou con algún fallo ou omitido fai fallar a fila. `--estrito` executa o comando literal de cada fila e é o modo de QA e o da CI semanal. Donos: `backend` · `frontend` · `infra` · `architect`.
