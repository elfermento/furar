# ADR-0008 · Erros RFC 9457 con código traducible

- **Estado:** aceptada · 2026-10-22 (revisada tras a revisión do equipo)

## Contexto
Un problema habitual: a API devolve erros en texto plano e a web espera un código que non chega. A app é bilingüe e a API terá consumidores de terceiros. Os erros que nacen en filtros (Spring Security, concello) non pasan polo `@RestControllerAdvice`.

## Decisión
Todo erro sae como `application/problem+json` (RFC 9457):

```json
{
  "type": "https://furar.gal/problemas/municipality.slug-taken",
  "title": "Xa existe un concello con ese identificador",
  "status": 409,
  "detail": "O identificador «naron» está en uso.",
  "instance": "/api/v1/municipalities",
  "code": "municipality.slug-taken",
  "params": { "slug": "naron" },
  "errors": [ { "field": "customFields.phone", "code": "customfield.invalid-format", "params": {} } ],
  "traceId": "4bf92f3577b34da6"
}
```

- **Un só escritor:** `shared.web.ProblemWriter` (MessageSource gl/es). Úsano o `@RestControllerAdvice`, `ProblemAuthenticationEntryPoint` (401 `auth.unauthenticated`, tamén JWT inválido ou caducado), `ProblemAccessDeniedHandler` (403 `auth.forbidden`), `TenantFilter` (404 `municipality.not-found`) e o `ErrorController` de Boot (404 de ruta, 405).
- **`AuthorizationDeniedException`** (método) ten handler propio → 403 `auth.forbidden`, antes do xenérico de `Exception` (500 `common.internal`).
- **`code`** estable, en inglés, `modulo.motivo-en-kebab`. Cada módulo ten `enum XxxError implements ErrorCode { CODE(status) }`; comúns en `CommonError` (`validation.failed`, `common.malformed-json`, `common.method-not-allowed`, `common.stale-version`, `common.internal`).
- **`title`/`detail`** traducidos no servidor (`messages_{gl,es}.properties`, segundo `Accept-Language`, gl por defecto). A web traduce polo `code` co seu catálogo e interpola `params`.
- **Validación** → 400 `validation.failed` con `errors[]` por campo.
- **Mapa fixo:** inexistente 404 · conflito 409 · regra de negocio 422 · versión vella 412 · sen sesión 401 · sen permiso 403 · interno 500 sen detalle técnico (só `traceId`).
- **Contrato:** o esquema `Problem` publica `code` como `enum` con todos os `ErrorCode` (ADR-0009).
- **Tests:** `ProblemDetailsIT` cobre sen token, token caducado, sen rol, slug inexistente, JSON mal formado, método non permitido, validación, 412 e 500 (forma e `content-type`). `ErrorCatalogTest` falla se un `ErrorCode` non ten texto en `messages_gl` e `messages_es`. Na web, `i18n:check` falla se un código do `enum` non está en `gl.json` e `es.json`.

## Consecuencias
- A web amosa sempre o erro no idioma do veciño e xunto ao campo afectado.
- Os códigos son contrato: cambialos é un cambio incompatible.

## Alternativas descartadas
- **Texto plano ou formato propio:** non estándar, non traducible.
- **Só `title` traducido no servidor:** a web non podería poñer o erro no campo nin cambiar de idioma sen nova petición.
- **Deixar os 401/403 por defecto de Spring:** corpo baleiro sen `code`; a web non podería explicalos.
